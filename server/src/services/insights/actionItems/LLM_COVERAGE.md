# LLM Usage Breakdown

## When We Use LLM vs Rule-Based

### ✅ Rule-Based (No LLM) - ~70% of Insights
Fast, deterministic, zero cost for these 34 types:

**Phase 1 - Pure Rules:**
- Outstanding balances
- Payment issues
- Contract renewals
- Storage capacity
- User limits
- API/transaction capacity
- Upgrade timelines

**Phase 2 - Template-Based:**
- Health score alerts
- Inactive customers
- High ticket volumes
- SLA breaches
- Stakeholder disengagement
- Recurring problems
- Feature requests

### 🤖 LLM-Enhanced - ~30% of Insights
Context-aware, intelligent generation for all other types:

**Strategic Insights:**
- Declining activity
- Solution gaps
- Adoption milestones
- Seasonality patterns
- Value correlation
- Technical debt
- Integration issues

**Advanced Stakeholder:**
- Influence concentration
- Engagement trends
- Decision maker activity
- Role adoption barriers
- Training opportunities

**Success Metrics:**
- KPI underperformance
- Metric targets
- NPS/CSAT below targets
- Custom satisfaction metrics

**User Engagement:**
- Usage patterns
- Power users
- Session engagement
- Feature discovery
- Anomaly detection

**NPS/CSAT:**
- All NPS insights
- All CSAT insights
- Feedback analysis
- Trend identification

## Why This Split?

- **High-frequency insights** (balances, capacity, health score) → Rule-based
- **Common but variable** (tickets, stakeholders, problems) → Templates
- **Strategic/complex** (correlations, patterns, success criteria) → LLM
- **Customer-specific** (NPS, CSAT, satisfaction) → LLM

This gives us the best balance of speed, cost, and intelligence!
